# 🧪 محاكي جزم متعدد اللاعبين (أداة تطوير)

**لا يُحمَّل في الموقع** ولا يؤثّر عليه — مجلّد اختبار فقط.

## ما هو؟
يشغّل **الكود الحقيقي** (`js/firebase.js` + `js/ui/onlineGame.js`) لعدّة لاعبين وهميين في وقت واحد،
كل لاعب في بيئة مستقلة (صفحة وهمية خاصة به)، فوق **Firebase وهمي في الذاكرة** وساعة افتراضية
(دقائق من اللعب تُحاكى في ثوانٍ). بدل فتح 3-4 تبويبات والتجربة يدوياً.

## ما يفحصه (v35.6)
**🎲 البحث الجماعي العشوائي**
1. العودة بعد الرفض (لاعبان: المنشئ ثم المنضم) → الاثنان في التصويت والمباراة تبدأ.
2. المنتظر (عاد أثناء تصويت الآخرين) → ينتظر، لا يدخل مباراتهم، ويعود للبحث.
3. عدّاد المجموعة يبدأ لحظة تكوّنها بلاعبَين، يكمل للثالث، والوحيد **بلا عدّاد**.
4. لا كتابات بحث أثناء مباراة جارية.

**👥 4 لاعبين**
5. الامتلاء يبدأ مباشرة بلا تصويت · الرابع يدخل أثناء التصويت فيكتمل العدد · أربعة يبحثون عن 3.

**🔑 الغرفة بالكود**
6. التاج وزر البدء للمضيف وحده · نص الزر: "ابدأ بلاعبَين (من 3)" بعدد ناقص و"ابدأ المباراة" + "اكتمل العدد" عند الاكتمال · البدء بلاعبَين من 3 · منع الانضمام بعد البدء · الغرفة الممتلئة.
7. المضيف يغادر بالزر → وريث واحد يبدأ · القادم الجديد يأخذ المقعد الفارغ ولا يسرق التاج.
8. المضيف السابق يعود → بلا زر بدء ولا يستطيع البدء.
9. المنشئ يغلق تبويبه → الغرفة تستمر والتاج ينتقل · الغرفة المهجورة لا تبتلع الباحثين.

**⚔️ البحث الثنائي**
10. الوحيد بلا عدّاد ثم المباراة عند انضمام خصم · الإلغاء يزيل الغرفة.

**🏁 نافذة نهاية المباراة** (`results.mjs` — من v35.5، ونهايات الخروج من v35.6)
11. الدالة النقية `core/matchResult.js`: لا مقاعد فارغة كلاعبين، كل جهاز يأخذ نتيجة مقعده، المتعادلون يتشاركون المركز،
    الخارج بالأسفل وخارج الفوز، المشاهد بلا نتيجة شخصية، مباراة اثنين من غرفة جماعية = واحد ضد واحد ضد الخصم الحقيقي.
12. `gameEnd.js` الحقيقي في بيئة معزولة: الأسطر المعروضة + كل ما يُسجَّل (إحصائيات، سجل، سلسلة، خبرة) لكل نوع مباراة.
    **إثبات:** على v35.4 يفشل 11 من 16 ويعيد خلل المستخدم حرفياً ("3. لاعب 1: 0 نقطة").
13. نهايات الخروج (23): فوز بانسحاب الخصم رغم التأخر بالنقاط + العملات، النهاية الثانية لا تسجّل ولا تضيف عملات،
    المنسحب بالزر خسارة بلا عملات ولا نافذة (وآخر المراكز بالجماعي)، والضيف بلا حساب والمشاهد لا يُسجَّل لهما شيء،
    ونهايتان متزامنتان، ومباراة جديدة تبدأ أثناء تسجيل السابقة (عملات السابقة تُثبَّت ونافذتها لا تُعرض فوق الجديدة).

**🚪 نهايات الانسحاب** (من v35.6 — المحاكي يلتقط كل نهاية عبر بديل `gameEnd.js`)
14. الثنائي: المنسحب بالزر تُسجَّل خسارته وخصمه يرى فوزه (نافذة واحدة رغم وصول إشارتين) · الخصم يغلق تبويبه → فوز
    للباقي والغرفة تعرف من انقطع (dropped1/dropped2) · **انقطاع حقيقي** (`drop()`) للمضيف أو المنضم، بما فيه
    "يعود قبل أن يلاحظ الخادم" → الباقي يفوز ومن انقطع لا يعلن فوزه · انقطاع طويل ثم خروج الفائز → العائد لا يعلن فوزه ·
    **مباراة ثانية** بعد الأولى: معالجات الأولى مفصولة، وانسحاب مبكر في الثانية يُسجَّل مرة واحدة ولا يضيع.
15. الجماعي: منسحب بالزر + منقطع أكثر من مهلة السماح وصفحته مفتوحة → آخر الباقين يفوز، والمنقطع الحاضر يرى
    "كنت خارجها" مع خسارته، ولا تكرار للنهاية · **ختم انقطاع متأخر** (الخادم ينفّذ onDisconnect القديم بعد العودة)
    لا يُخرج اللاعب المتصل.
    `drop()` يحاكي Firebase 10.12: الاتصال يسقط أولاً، وأوامر onDisconnect تُطبَّق **محلياً** على جهاز المنقطع،
    والخادم ينفّذها لاحقاً (حتى بعد العودة)، ولا أحداث للمنقطع، وget ينتظر العودة، ثم إعادة تزامن.

**🔎 مستكشفات عشوائية** (أفعال عشوائية + ثوابت لا يجوز كسرها أبداً)
- البحث الجماعي بـ3 وبـ4 لاعبين: لا مقاعد مكرّرة، لا عدّاد عند وحيد، لا مجموعة عالقة،
  لا كتابات في الهدوء، ولا لاعب داخل مباراة لم يصوّت عليها.
- الغرفة بالكود بـ4 لاعبين (انضمام/مغادرة/بدء عشوائي): تاج واحد متّفق عليه وحامله حاضر،
  وزر البدء عند حامل التاج وحده، ومباريات متّسقة.

**⚠️ أخطاء معروفة** (تُعرض ولا تُفشل الفحص — للدفعة التالية):
سباقات الانضمام في البحث الثنائي (الخطوة 1.3).

## التشغيل
```bash
cd tests/sim
npm install              # مرة واحدة

npm run quick            # مستكشفات أقصر
node --experimental-vm-modules --no-warnings run-all.mjs --only="الغرفة بالكود"   # قسم واحد
```
